A typical conversation loads ~13 KB of always-loaded files. On-demand docs are added only when needed — a database task might add SCHEMA.md (+20 KB) and CREDENTIALS.md (+8 KB), bringing the total to ~41 KB. The maximum possible context from all config files is ~160 KB, but this rarely happens in practice.

Auto-loaded Always in Context

These files are automatically loaded into every Claude Code conversation. They define the core rules and behaviors.

CLAUDE.md

4 KB 39 lines Always loaded
Project directives — the primary instruction file for Claude Code. Defines mandatory behaviors (version reporting, push workflow, decision logging), code guards (naming conventions, UI patterns, Tailwind tokens), and pointers to on-demand documentation. Acts as the root of the configuration tree.
Points to: docs/CREDENTIALS.md, docs/SCHEMA.md, docs/PATTERNS.md, docs/KEY-FILES.md, docs/DEPLOY.md, docs/INTEGRATIONS.md, docs/CHANGELOG.md, PRODUCTDESIGN.md

CLAUDE.local.md

~1 KB ~20 lines Always loaded
Operator directives — private, not checked into git. Contains DB access shortcuts (Supabase Management API bearer token pattern), push workflow overrides (always push immediately, CI bumps version), SQL migration instructions, and live URLs for the production site.
Points to: docs/CREDENTIALS.md (for DB access), version.json

version.json

4 KB 12 lines Always loaded
Release metadata — CI-generated file updated on every push to main. Contains the current version string (vYYMMDD.NN H:MMa format), release sequence number, Git SHA, actor, source, and commit messages. Read after every push to report the deployed version.

On-demand Documentation Files

Loaded into context only when the task matches specific triggers defined in CLAUDE.md. Keeps context lean for simple tasks.

docs/CREDENTIALS.md

~8 KB On-demand
Secrets & access — Supabase project keys (anon + service role), Management API token, edge function deploy commands, SSH credentials for Hostinger VPS and Alpaca Mac, and external API keys. Loaded when running SQL, deploying functions, SSH-ing, or making API calls.

docs/SCHEMA.md

20 KB 347 lines On-demand
Database schema — complete Supabase/PostgreSQL table definitions. Core tables (spaces, people, assignments), media system, SMS, email, payments (Stripe, Square, PayPal), smart home devices (Nest, Tesla, Govee, LG, Sonos), PAI configuration, and more. Loaded when writing queries, modifying tables, or debugging data.

docs/PATTERNS.md

8 KB 118 lines On-demand
UI conventions — Tailwind CSS design tokens (aap-* naming), Supabase query patterns for fetching spaces with media, computing availability, and standard code snippets. Loaded when writing UI code, styling with Tailwind, or during code review.

docs/KEY-FILES.md

16 KB 181 lines On-demand
File directory — comprehensive listing of every significant file in the project, organized by module: shared modules, mobile app, payment page, consumer view, admin view, resident view, associate view, PAI Discord bot, and all Supabase edge functions with their deploy flags.

docs/DEPLOY.md

4 KB 40 lines On-demand
Deployment workflow — GitHub Pages push workflow (git add, commit, push), post-push verification steps, version format (vYYMMDD.NN H:MMa), live URL table (custom domain, GitHub Pages, resident portal, admin, public spaces, payments), and Tailwind CSS build command.

docs/INTEGRATIONS.md

32 KB 496 lines On-demand
External APIs & cost accounting — API usage logging requirements, vendor list (Google, Telnyx, Resend, Vapi, SignWell, Stripe, Square, PayPal, Tesla, LG, Govee, Anova, Glowforge, FlashForge), cost-per-unit tables, and integration setup instructions for each external service.

docs/CHANGELOG.md

32 KB 368 lines On-demand
Recent changes — chronological log of significant platform changes: hero banner redesign, consumer availability, media migration, space archiving, rental pipeline, SMS integration, payment processing, AI features, and more. Loaded for understanding migration context or recent architectural decisions.

PRODUCTDESIGN.md

40 KB 511 lines On-demand
Product design decisions — the "why" behind AlpacApps. Covers the no-framework philosophy, business model, financial reasoning, UX tradeoffs, and architectural decisions. Captures every significant decision with rationale. Updated whenever Claude makes significant choices. The largest documentation file.
Updated by: Claude Code (mandatory behavior #2 — log decisions with "Decision" and "Why")

Settings Claude Code Configuration

JSON configuration files in .claude/ that control Claude Code's runtime behavior.

.claude/settings.json

4 KB 5 lines Always loaded
Environment settings — sets ENABLE_LSP_TOOL=1 to enable TypeScript Language Server Protocol support in Claude Code for better code intelligence.

.claude/settings.local.json

~2 KB Always loaded
Local settings — private, not checked into git. Contains user-specific Claude Code preferences, permission rules, and MCP server configurations.

.claude/launch.json

4 KB 24 lines Always loaded
Dev server configurations — defines local development servers: alpacapps (Python HTTP server on port 8090), mistiq-cards (port 8092), and finleg (npm dev on port 3001). Used by Claude Code's preview tools for local development.

Memory Persistent Memory Files

Claude Code's persistent memory system — stored in ~/.claude/projects/, indexed by MEMORY.md. These survive across conversations.

MEMORY.md

~4 KB Always loaded
Memory index — always loaded into context (first 200 lines). Contains the master index of all memory files, data lookup routing tables (which Supabase table to query for what question), quick DB query template, and important gotchas (SSH access, Hostinger workarounds, Uptime Kuma constraints).
Points to: memory/sessions.md, memory/service-access.md, memory/cloud-infra.md, memory/session-archive.md

memory/sessions.md

On-demand
Session summaries — log of significant Claude Code sessions with what was accomplished, decisions made, and context for future conversations.
