Before you start

Install your AI desktop app, then sign up for five services

Everything here is simple, click-only work you can finish before the real setup begins. Install Claude Desktop or ChatGPT Desktop first, then let it sit beside you and answer questions while you create the five accounts AlpacApps needs. No terminal, no code.

20–40 minutes · no coding

What you’ll do on this page

  1. Pick and install one AI desktop app — Claude Desktop or ChatGPT Desktop (Codex). This is your helper for everything else.
  2. Set up a password manager so every password and key has one safe home.
  3. Create five free accounts — Supabase, GitHub, Cloudflare, Google Cloud, and Resend — with your AI app answering questions as you go.
  4. Move on to setup at alpacaplayhouse.com/infra, where your assistant builds and deploys the project.
  5. Optional: add a cheaper coding model — the only step here that needs a credit card.

Nothing here is irreversible. You are only creating accounts. You do not need to create projects, API keys, tokens, or domains yet — the setup wizard does that later, once it knows your app name and domain.

Step 2 — Open it and paste this prompt

Start a normal chat conversation (not Claude Code, not Codex) and paste the prompt below. Your assistant will then walk you through each signup in order, tell you exactly what to click, and read any screenshot you paste when you get stuck.

I'm getting ready to set up an AlpacApps project. Before the real setup starts, help me create accounts for these five services, one at a time, in this order: Supabase, GitHub, Cloudflare, Google Cloud, and Resend. For each one: give me the exact signup URL, tell me what to click, tell me what to write down afterward, and wait for me to say "done" before moving to the next one. I may paste screenshots — tell me if I'm on the right page. Do NOT have me create API keys, tokens, projects, or domains yet. Account creation only. Reference: https://alpacaplayhouse.com/infra/prestart

Stay in chat for now. If your assistant starts asking you to pick a folder, clone a repo, or run terminal commands, you have wandered into Claude Code or Codex. Go back to the plain chat tab — the coding tools come later, on the setup page.

Step 3 — Set up one safe place for passwords

You are about to create five accounts. Decide where the passwords live before you make them, not after.

Best option: password manager

  1. Use your existing password manager if you have one.
  2. If not, install Bitwarden (free) and create an account.
  3. Install the browser extension so it generates and saves strong passwords during each signup.
  4. Create a folder called AlpacApps Setup.
  5. Save one login item per service as you go.

Okay option: a private doc

  1. Create a doc named AlpacApps Account Setup.
  2. Set sharing to Restricted — never link-access or public.
  3. Track usernames, service URLs, and status only.
  4. For any secret, write “stored in password manager” instead of the value.

Never paste secrets into public places. No passwords, API keys, OAuth client secrets, recovery codes, or database passwords in a public doc, GitHub issue, Slack channel, screenshot, or a file committed to your repo.

Want a ready-made tracker to fill in? The account setup checklist has a copyable credential template.

Step 4 — Create the five accounts

Work top to bottom. Each one is free to start, and each takes a few minutes. Ask your assistant whenever a screen does not look like the description.

1. Supabase

Free tier

Your database, user logins, file storage, and edge functions — the backend of your app.

Do this

  1. Go to supabase.com/dashboard/sign-up.
  2. Sign up (signing in with GitHub is fine if you make GitHub first).
  3. Create a free organization if prompted.
  4. Stop there — do not create a project yet.

Write down

  • Login email
  • Organization name
  • Password manager item name

Why wait on the project: the wizard names it, picks the region, and sets the auth URLs to match your app. If you do create one anyway, save the database password immediately — Supabase never shows it again.

2. GitHub

Free

Where your code lives, and where your assistant commits and pushes every change.

Do this

  1. Go to github.com/signup.
  2. Pick a username you are happy to see in URLs.
  3. Verify your email address.
  4. Turn on two-factor authentication and save the recovery codes.

Write down

  • Username
  • Login email
  • Where the 2FA recovery codes are saved

No access token needed. Setup signs you in through the GitHub CLI browser flow, so skip Personal Access Tokens entirely.

3. Cloudflare

Free core

DNS for your domain, Cloudflare Pages hosting, D1 session logging, and R2 file storage.

Do this

  1. Go to dash.cloudflare.com/sign-up.
  2. Create the account and verify your email.
  3. Already own a domain? You can add it now, or let the wizard walk you through it later.
  4. Don’t own one? Skip it — a free github.io address works to start.

Write down

  • Cloudflare email
  • Account name
  • Domain name, if you have one

Optional head start: open Profile → API Tokens, find Global API Key, click View, and save it in your password manager. Setup uses it once to mint a narrower project-scoped token.

4. Google Cloud

Free

Supplies the OAuth client behind “Sign in with Google” in your app.

Do this

  1. Decide which Google account should own your app’s login settings.
  2. Sign in at console.cloud.google.com and accept the terms.
  3. Optional: create a project at projectcreate and name it after your app.
  4. Stop before creating OAuth credentials.

Write down

  • Google account email
  • Project name and Project ID, if created

OAuth comes later on purpose. The redirect URI has to be https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback, and that project ref does not exist yet.

5. Resend

Free tier

Sends your app’s email — welcome messages, confirmations, notifications.

Do this

  1. Go to resend.com/signup.
  2. Create the account and verify your email.
  3. Skip domain verification for now — it needs Cloudflare DNS records the wizard will add.
  4. Skip the API key too; setup creates and validates it in place.

Write down

  • Resend login email
  • Which domain you plan to send from, if known

Optional — a cheaper coding model (DeepSeek v4 Flash via OpenRouter)

Skip this unless you already know you want it. Everything above is free or free-tier. This section is the one place that asks for a credit card, and nothing in AlpacApps requires it.

Once you are building a lot, most of the tokens go to grunt work — renaming things, filling in boilerplate, applying the same edit across twelve files. That work does not need a frontier model. The pattern here is orchestrator plus worker:

Orchestrator — Claude Sonnet (Luna)

  • Reads the codebase and decides what to change
  • Writes the plan and the precise instructions
  • Reviews what came back and fixes what is wrong
  • Stays on your Claude subscription

Worker — DeepSeek v4 Flash

  • Executes the mechanical edits it was handed
  • Runs through OpenRouter, billed per token
  • Dramatically cheaper per token than a frontier model
  • Never decides architecture on its own

The split matters. Judgment stays with the orchestrator; only well-specified work goes to the cheap model. If you hand DeepSeek open-ended design decisions, you will spend the savings back on cleanup.

OpenRouter

Credit card

OpenRouter is one API key that reaches many models, DeepSeek included. It runs on prepaid credits, so you add a payment method and buy a balance up front rather than getting a monthly bill.

Do this

  1. Sign up at openrouter.ai and verify your email.
  2. Open Settings → Credits and add a card.
  3. Buy a small starting balance — $5 to $10 is plenty to see whether you like the workflow.
  4. Create a key at Settings → Keys and set a credit limit on the key itself, so a runaway loop cannot drain the balance.
  5. Save the key in your password manager the moment it appears — OpenRouter shows it once.
  6. Find the current DeepSeek entry on openrouter.ai/models and copy its exact model slug.

Write down

  • OpenRouter login email
  • API key — password manager only, never in the repo
  • The exact DeepSeek model slug you chose
  • The per-key credit limit you set

This one actually charges you. Turn off auto-recharge until you know your usage, keep a per-key credit limit on, and check Activity after your first heavy session. The key goes in .env as OPENROUTER_API_KEY — and .env is never committed.

Confirm the model before you rely on it. DeepSeek ships fast and slugs change. Pull the current name off the models page rather than trusting a slug written down here, and tell your assistant which one you picked.

What to tell your assistant later: “I have an OpenRouter account with credits and a key saved. Set up DeepSeek as the worker model for mechanical edits, with Sonnet orchestrating.”

You’re ready

You are done with pre-start when you can sign in to all five services and you know where the saved credentials live.
