Overview

AlpacApps runs on Supabase. Every endpoint is a Supabase edge function at:

https://aphrrfprbixmhissnjfn.supabase.co/functions/v1/<function>

The main one is the api gateway. It's a single permissioned endpoint for reading and writing records such as spaces, people, bookings, rentals, tasks and documents. Everything is a POST with a JSON body that names a resource and an action:

POSThttps://aphrrfprbixmhissnjfn.supabase.co/functions/v1/api
Building an agent or an integration? Start with a scoped API key and the rentals resource. Agent recipes has copy-paste calls.

Getting an API key

API keys are the right way to give an external agent access. Each key is a row in api_keys, and the database stores only a SHA-256 hash of the key, never the key itself. A key is limited three ways:

  • Level: the role it acts as. Agent keys are usually level 2 (staff).
  • Allowed resources: for example only rentals, rental_notes and vehicles. Any other resource returns 403.
  • Allowed actions: for example list, get, create. A key can never do more than its level allows. Deletes on rental_notes need admin, so a staff key can't remove notes.

Keys start with amk_, and each call updates the key's last_used_at. To revoke a key, set is_active = false on its row. It stops working on the next request.

Issuing a key (admins): run scripts/create-api-key.js --name "…" --level 2 --resources rentals,rental_notes --actions list,get,create. It prints the key once. Store it in Bitwarden straight away, then paste it into the agent's secret or credential settings. Never paste it into the agent's prompt or into a chat.

Request & response

{
  "resource": "rentals",          // required
  "action":   "list",             // list | get | create | update | delete
  "id":       "…",                // get / update / delete
  "data":     { … },              // create / update
  "filters":  { … },              // list
  "limit":    100,                // default 100, max 500
  "offset":   0,
  "order_by": "created_at",       // most resources
  "order_dir":"desc"
}

A success returns {"data": …, "count": 42, "error": null}. A failure returns {"data": null, "error": "message", "code": 4xx}.

403The caller's level is too low, or the API key isn't scoped for this resource or action

rentals new

A read-only view of every rental agreement in one shape, for answering "when does each rental start and end, and what happens at the end?". It covers:

  • Space bookings: both Airbnb guests, synced from Airbnb's calendar, and direct tenants on a lease.
  • Vehicle rentals.

Levels: list and get need level 2.

Month-to-month vs fixed end dates

An end date can mean two different things:

end_behaviorWhat happens on end_datePlan around…
month_to_monthThe initial term ends, but the rental automatically continues monthly until either side gives notice (notice_days). If end_date is null it's open-ended from the start.Don't treat end_date as a move-out. Check planned_move_out and the notes.
fixedThe rental ends. The renter leaves unless a new agreement is made. Every Airbnb booking is fixed; an extension shows up as a changed end_date once it's confirmed in Airbnb.Treat end_date as the move-out and turnover date.
unknownThe agreement doesn't record which it is. This is common for older direct leases entered by hand.Ask a human, or ask an admin to set it.

How it's decided, first match wins:

  1. An admin set it explicitly on the booking (assignments.end_behavior).
  2. It's an Airbnb booking, so it's fixed.
  3. It came through a lease application: a notice period of "none" means fixed, any other notice period means month-to-month.
  4. It has no end date, so it's month-to-month.
  5. Vehicle rentals use their auto-renew setting.

Anything else is unknown.

rental_notes new

Free-text notes attached to one rental, for Airbnb guests and direct tenants alike. For example: "Airbnb guest is planning to extend but hasn't finalized yet." Notes are append-only for agents, and every note records who wrote it (the API key's name or the user's name).

ActionLevelBody
create2data: { rental_id, body, tag? }. rental_id is the id from rentals. body is up to 4000 characters. tag is an optional short label, e.g. extension, move_out, payment, general.
list2filters: { rental_id?, tag?, since? }, newest first
get2id
delete3 (admin)id

A note object looks like { id, rental_id, body, tag, author, created_at }.

Agent recipes

Set KEY to the API key from the agent's secret store.

# Everything ending in the next 30 days, soonest first
curl -s https://aphrrfprbixmhissnjfn.supabase.co/functions/v1/api \
  -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"resource":"rentals","action":"list",
       "filters":{"ends_after":"2026-10-17","ends_before":"2026-11-16"}}'

# Leases that really end (no automatic monthly rollover)
  -d '{"resource":"rentals","action":"list","filters":{"end_behavior":"fixed","source":"direct"}}'

# Which Airbnb guest is in Skyloft?
  -d '{"resource":"rentals","action":"list","filters":{"source":"airbnb","space":"skyloft"}}'

# Attach a note to that booking (use the id from the previous call)
  -d '{"resource":"rental_notes","action":"create",
       "data":{"rental_id":"assignment:<uuid>","tag":"extension",
               "body":"Airbnb guest is planning to extend but hasn'\''t finalized yet."}}'
Airbnb guests have no names in our data. To find "the Airbnb guest in Skyloft", list with source: "airbnb" plus space, then pick the booking whose dates cover today. If more than one could match, ask a human instead of guessing.

Smart behaviors

  • Fuzzy names: fields like assigned_name and space_name resolve to ids for you, e.g. "Jon" or "skyloft".
  • Auto-timestamps: fields like completed_at and updated_at are set by the server when status changes.
  • Row scoping: residents and associates only see their own bookings, hours and events.
  • Usage logging: every call is logged against the user or API key.

Webhooks & internal functions

These aren't for outside callers. They're listed so you know they exist and don't build against them:

  • Inbound webhooks, each verified by its provider's signature: Stripe, Square, PayPal, Resend (email), Telnyx (SMS), WhatsApp, Vapi (voice), Alexa.
  • Scheduled jobs: the Airbnb calendar sync, iCal regeneration, payment and payroll reminders, weekly reports and nightly tests.
  • Token-link flows opened from emails: lease signing, identity verification, W-9, email approval, deposit confirmation.

Missing something? Endpoints for agents should be added to the api gateway as a scoped resource, not as a new standalone function, so API keys, levels and logging all work the same way.
