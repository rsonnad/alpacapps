Local AI Models on Alpuca

Reference for the open-weight LLMs running on the Alpaca Playhouse Mac mini, served via Ollama. If your project has LAN or tailnet access to the host, this page tells you what's available and how to call it.

Hardware

One Apple Silicon Mac mini (M4, 24 GB unified memory) serves as the local AI host. Models are stored on attached fast NVMe and loaded into memory on demand. Only one large model is resident in RAM at a time — Ollama swaps automatically when you call a different one.

Why the 30 B Qwen models feel fast MoE

The Qwen 3 30B-A3B family uses a mixture-of-experts architecture. The model has 30 billion total parameters on disk, but only about 3 billion activate per token. Runtime cost is closer to a small dense model while the model retains the knowledge of a much larger one. This is what makes it practical to run on a Mac mini.

By contrast, deepseek-r1:32b is dense — all 32 B parameters fire on every token, and it generates many internal “thinking” tokens before producing the final answer. Plan for tens of seconds per response.

Calling the models

Ollama exposes two HTTP endpoints on port 11434 — its own native API and an OpenAI-compatible chat endpoint. From the host machine:

Native API

curl -s http://localhost:11434/api/generate -d '{
  "model": "qwen3:30b-a3b",
  "prompt": "Summarize git rebase in one sentence.",
  "stream": false
}' | jq -r .response

OpenAI-compatible (drop-in for any OpenAI SDK)

curl -s http://localhost:11434/v1/chat/completions -d '{
  "model": "qwen3-coder:30b",
  "messages": [{"role":"user","content":"Write a TypeScript isEmail()."}],
  "temperature": 0.2
}' | jq -r '.choices[0].message.content'

Vision (image input via base64)

B64=$(base64 -i screenshot.png | tr -d '\n')
curl -s http://localhost:11434/api/generate -d "$(jq -n \
  --arg img \"$B64\" \
  '{model:\"qwen3-vl:30b-a3b\",
    prompt:\"Describe this screenshot.\",
    images:[$img], stream:false}')" | jq -r .response

Thinking mode toggle (Qwen 3)

Prefix a prompt with /think to get chain-of-thought reasoning, or /no_think for a direct response. Default is direct.

ollama run qwen3:30b-a3b "/think What is 17 * 24?"

Calling from another machine or another repo

Ollama listens on all interfaces on port 11434, so any client on the same LAN (or joined to the tailnet) can call it directly — no SDK install, no model download. Replace localhost in the examples above with the Alpuca host you can reach.

Network-level access only. Ollama has no auth by default. Anyone who can reach 11434 can use the models. Keep the host behind your LAN, VPN, or tailnet — do not port-forward to the public internet.

Recommended pattern: one env var, one base URL

In any consumer repo, define a single environment variable for the base URL and let everything else read from it:

# .env (or your platform's secret store)
ALPUCA_OLLAMA_URL=http://<alpuca-host>:11434

# Then in code (any language with an OpenAI SDK):
#   baseURL = `${process.env.ALPUCA_OLLAMA_URL}/v1`
#   apiKey  = "ollama"          // value is ignored, but most SDKs require non-empty

The actual host (LAN IP or tailnet name) lives in your project's credentials store, not on this public page.

Discover what's loaded right now

List installed models programmatically — useful for guard clauses in scripts that fail gracefully if a model isn't pulled:

curl -s $ALPUCA_OLLAMA_URL/api/tags | jq -r '.models[].name'

Liveness check (CI / health monitor)

curl -fsS --max-time 3 $ALPUCA_OLLAMA_URL/api/tags > /dev/null \
  && echo "alpuca ollama OK" || echo "alpuca ollama DOWN"

Node.js (using the OpenAI SDK)

import OpenAI from "openai";

const client = new OpenAI({
  baseURL: `${process.env.ALPUCA_OLLAMA_URL}/v1`,
  apiKey: "ollama", // ignored by Ollama, but the SDK requires a value
});

const r = await client.chat.completions.create({
  model: "qwen3-coder:30b",
  messages: [{ role: "user", content: "Write a TypeScript isEmail()." }],
});
console.log(r.choices[0].message.content);

Python (using the OpenAI SDK)

from openai import OpenAI
import os

client = OpenAI(
    base_url=f"{os.environ['ALPUCA_OLLAMA_URL']}/v1",
    api_key="ollama",
)

r = client.chat.completions.create(
    model="qwen3:30b-a3b",
    messages=[{"role": "user", "content": "Summarize git rebase in one sentence."}],
)
print(r.choices[0].message.content)

Things to know before integrating

  • One model at a time — the host has 24 GB RAM. Calling a different model triggers a 15–30 s warm-up while it swaps in. Pin your service to a single model when possible.
  • No rate limiting at the server — if you hammer it from multiple clients, requests queue. Plan for ~5–15 s per response on the 30 B models, much longer if deepseek-r1 is the target.
  • Streaming works — set stream: true for token-by-token output. Useful for UIs and progress indicators.
  • Default keep-alive is 5 minutes — after that idle, the model unloads from RAM and the next call eats the warm-up.
  • Availability — the host is a Mac mini, not enterprise infra. Treat it as best-effort. For high-availability traffic, fall back to a cloud provider.

Local vs cloud Claude — choosing

The local stack exists to be useful, not to replace cloud Claude. Treat them as different tools.

TaskUse
High-stakes reasoning, design judgment, code review you depend onCloud Claude (Opus / Sonnet)

Describing or extracting info from imagesqwen3-vl:30b-a3b

Desktop UI

The cleanest way to chat with the local stack is msty — a free native macOS app that auto-detects Ollama at http://localhost:11434 and lets you switch providers mid-conversation, branch threads, and drop files into knowledge bases.

For programmatic use, any OpenAI SDK works by pointing the base URL at http://localhost:11434/v1.
