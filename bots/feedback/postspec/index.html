Feedback posting spec

For any bot (Avatar Profile Designer first) that passes its user's feedback to its creator. Read this once, follow it every run.

What the bot does

  1. Once per run, after the main work is delivered, it offers to pass on feedback.
  2. If the user gives some, the bot writes it as a short note and shows it back.
  3. It asks whether to include the user's email so the creator can reply.
  4. It sends the note only after the user says yes, then says whether it worked.

1. The offer

Say this once per run, at the end, in the user's language:

And if you have any feedback or ideas for improving my work, I can pass them to my creator.

  • Never ask twice in one run, and never interrupt the main task to ask.
  • If the user ignores it or says no, drop it.
  • If the user brings up a problem or idea on their own at any time, you may offer to pass it on then instead.

2. Write the note and show it

Turn what the user said into a plain note, in their words where possible. Pick one type:

typeUse when the user…
feedbacksays what they liked or didn't (default)
feature_requestasks for something new or different
bugreports something broken or wrong

Show it before sending, for example:

Here's what I'll send: "Let me pick a different style for each of my bots." (idea) Should I include your email so they can reply? It's optional.

  • Leave out passwords, keys, payment details, addresses, phone numbers and anything about other people.
  • Don't add your own opinions or summarise the whole chat. One note, at most 5000 characters.

3. Ask about email, then confirm

  • Include an email only if the user says yes and gives it, or confirms one they already gave you in this run.
  • Never guess an email or take one from an account, profile or earlier run.
  • Send only after a clear yes to the note (with or without email). A change request means show the new note and ask again.

Tell the user: "We store your message and, if given, your email to follow up."

4. Send it

POST https://alpacaplayhouse.com/bots/feedback

curl -X POST https://alpacaplayhouse.com/bots/feedback \
  -H "Content-Type: application/json" \
  -d '{"message":"Let me pick a different style for each of my bots.","type":"feature_request","email":"optional@example.com","bot_name":"Avatar Profile Designer","bot_version":"1.0"}'
FieldRequiredValue
messageyesThe note the user approved. Plain text, 1–5000 characters.
typenofeedback (default), feature_request or bug
emailnoOnly with the user's yes. Leave the field out otherwise.
bot_nameyes for botsYour public name, e.g. Avatar Profile Designer
bot_versionyes for botsYour template version, e.g. 1.0

No sign-in, key or cookie. Send JSON with Content-Type: application/json.

5. Read the answer and tell the user

AnswerMeansTell the user
201 {"ok":true,"id":"…"}Stored"Sent. Thank you!"
400 {"ok":false,"error":"…"}Something in the note is wrong; error says whatFix it (e.g. shorten), show the note again, ask again
429Too many notes from this address this hour"I couldn't send it right now. You can also use alpacaplayhouse.com/bots/feedback/ later."
5xx or no answerServer problemRetry once after a few seconds; if it fails again, say so and give the link above
  • Do say "sent" only after a 201.
  • Don't retry a 400 or 429 unchanged, and never send the same note twice.

Check your bot before release

  1. Offer appears once, at the end of a run, and not again.
  2. Saying no or ignoring it sends nothing.
  3. A note without email sends after a yes and you get 201.
  4. A note with email sends only after the user agreed to include it.
  5. A changed note is shown again before sending.
  6. A 6000-character note is shortened or refused before sending, never sent and ignored.
